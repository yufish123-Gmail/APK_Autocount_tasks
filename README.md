# APK_Autocount_tasks

将 [Mgame-auto-count-tasks](https://github.com/yufish123-Gmail/Mgame-auto-count-tasks) 的任务辅助功能移植为可安装的 Android APK。在用户授权并主动启动后，由手机完成界面识别、操作、计时、返回和奖励核对。

本仓库创建于 2026-11-26，目前已完成移植范围和技术方案整理，后续从 Android 工程和只读原型开始实施。APK 构建、手机端任务执行及完整真机验收均待实现。

## 项目目标

- 安装后由手机独立运行，日常使用无需连接电脑或 USB 调试。
- 保留按平台实际进度续跑、有限重试、奖励校验、停止和人工接力。
- 为八个日常阶段提供统一入口，为「跳转登录 APP 领奖励」提供独立入口。
- 支持查看阶段进度、暂停、停止及导出诊断记录。

首版建议使用 Kotlin、Android 无障碍服务、OpenCV Android 和内置中文 OCR。最低支持 Android 11（API 30），优先适配现有 1080×2400 竖屏设备。目标手机系统版本、ABI 和窗口可读性在开发前核对，Android SDK 与依赖版本在工程初始化时验证并固定。

## 移植范围

| 功能 | 需要保留的行为 |
|---|---|
| 浏览页面 | 识别任务行、按要求浏览、返回核对轮次 |
| 浏览好物 | 支持已确认的站内及外部落地页，按实际进度续跑 |
| 优惠活动 | 支持 5 秒和 10 秒任务行。已确认的 5 秒站内浏览保留 2 秒余量，广告遵循各自时长 |
| 60 秒游戏 | 常规等待 62 秒。回列表后仍确认同一游戏可执行时，最多前台补跑一次，沿用 70 秒设置 |
| 10 秒浏览 | 识别闪电奖励和对应小字，按页面实际奖励核对到账 |
| 20 秒游戏 | 沿用 22 秒等待及同一任务领奖校验 |
| 听书 | 确认播放后连续计时 32 秒，退出后核对奖励 |
| 短剧 | 在播放页连续计时 62 秒，退出后核对奖励 |
| 跳转登录 APP 领奖励 | 独立启动。从美团任务入口跳转，确认目标 APP 前台后连续停留 10 秒，返回领取并核对总进度 |
| 游戏中心导航 | 迁移原项目已实现的入口导航与桌面提示处理，核对目标首页 |

任务数量、名称和奖励以运行当天平台显示为准。日常入口依次执行上述前八项。独立跳转奖励、游戏中心导航分别由用户主动选择。

## 手机如何执行

任务引擎串行执行以下流程。

```text
用户选择任务并启动
    → 检查授权与屏幕状态
    → 无障碍窗口信息 + 截图
    → 控件 / 模板 / 中文 OCR 识别
    → 重新确认当前页面和任务
    → 点击、滑动、返回或等待
    → 核对平台进度和实际到账
    → 下一项 / 有限恢复 / 人工接力
```

无障碍控件可用时优先使用控件动作，自绘页面采用截图定位和手势。跨 APP 跳转保留美团任务里的原始入口。返回后先读取任务状态，避免重复计时或领取。

桌面版的 ADB、Windows OCR 和 Windows 会话锁需要替换。普通 APK 的恢复流程采用返回、唤回美团及重新进入任务页。美团确需强制停止时，由用户操作后继续核对进度。详细接口、方案比较与权限依据见 [APK 移植技术分析](docs/APK移植技术分析.md)。

## 授权和运行条件

| 能力 | 授权方式 |
|---|---|
| 观察窗口和操作屏幕 | 用户在系统设置中开启本应用的无障碍服务 |
| 截图与手势 | 服务声明读取窗口、手势和截图能力，使用 Android 对应接口 |
| 运行状态通知 | 需要通知控制时，按 Android 版本申请通知权限 |
| 安装 APK | 使用签名安装包，由用户通过系统安装器安装。受限设置按系统提示由用户确认 |
| 日志与截图 | 保存在应用私有目录，需要导出时由用户选择分享或保存 |

首版采用无障碍截图。MediaProjection 作为后续按需评估的替代采集方式，其会话授权和前台服务需要单独实现。手机运行时需解锁并保持可操作。遇到拼图验证、登录、系统授权、应用锁或受保护画面，暂停并提示用户接手。

接口依据见 [Android 无障碍服务](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[内置中文 OCR](https://developers.google.com/ml-kit/vision/text-recognition/v2/android?hl=zh-cn) 和 [应用专属存储](https://developer.android.com/training/data-storage/app-specific)。

## 实施顺序与验收

1. 创建 Android 工程，完成无障碍授权引导、单会话管理和停止控制。
2. 做只读原型，验证前台包名、截图、任务标题、按钮和次数识别，并校准屏幕坐标。
3. 完成一个浏览或独立跳转任务，验收点击、有效计时、返回和实际到账。
4. 逐项迁移八个日常阶段、独立跳转和游戏中心导航，覆盖截图失败、切页、迟到奖励和人工接力。
5. 生成签名 APK，在手机断开电脑后验收安装、授权、单项、全流程及中断续跑。

验收记录应包含 APK 版本、手机与系统版本、任务初始及最终进度、到账增量、耗时、恢复次数和证据路径。计时完成与奖励确认分别记录。完整流程提速结论需结合相同任务数量和真实运行耗时。
